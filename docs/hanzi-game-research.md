## 1. 结论先行

GitHub 上已经有几条值得借鉴的实现路线，但没有必要直接 Fork 一个项目作为 Hanzis 的新主干。最稳妥的方向是复用现有内容能力和视觉系统，自研轻量、短局、可重复游玩的小游戏。

扩展调研后新增的判断：

- 商店里评分最高、评论最多的汉字类游戏是**成语消除 / 成语填字**（成语消消消 27 万评分、成语接龙 14 万评分、成語消消挑戰 3.5 万评论），玩法本身已被大规模验证；差评集中在“每关插广告”和“成语顺序颠倒 / 释义要付费”。Hanzis 无广告、有释义来源，这两点正是差异化空间。
- 儿童识字 / 拼音头部 App（洪恩识字 143 万评分、洪恩拼音 51 万、悟空识字 12 万）的共同结构是“认 → 练 → 写 → 复习”闭环 + 绘本应用 + 家长控制，而不是单一小游戏；它们的差评（游戏成分过多、可随时退出学习环节、不能筛选重学）提示小游戏必须绑定明确的学习产出。
- 诗词类的成熟形态是**飞花令**：西窗烛（4.9 分、46 万评分）把飞花令、诗词接龙、诗词大会作为内置游戏；独立飞花令 App 与多个 2026 年网页项目都在做“单字 / 主题飞花 + 人机对战 + 词库判定”。Hanzis 已有 11,407 篇诗词和自动拼音，飞花令的内容门槛已经跨过。
- 每日一题的成语 Wordle 在网页端仍有活跃新作（wordlechinese.com、recatools 每日成语、xyz2357/cnwordle），其价值主要在“确定性每日题 + 本地 streak + 不泄题的分享网格”，可作为后续留存机制的参考。
- 对外汉语综合 App（HelloChinese 4.9 / 2.3 万、Skritter 4.7 / 789）以订阅制课程为核心，游戏化只是包装；对 Hanzis 的参考价值在于拼音课程结构和手写反馈，而不是产品形态。
- X 站内检索在本次工具环境下返回 0 结果，且正文需登录，未能作为一手来源；相关传播证据仅来自少数派等二手记录。

推荐顺序（相对 09-19 版的调整以 **[调整]** 标注）：

1. **P0：汉字词语消除**。参考 `lapsea/hanzi-match-game` 与商店成语消除类的差评清单，规则直观、题库容易校验、无需音频，适合先做成独立路由。
2. **P0：拼音快答**。参考 `vivianluchen/PinyinGame` 的模式、计时、得分和提示闭环，参考洪恩拼音 / Pinyin Academy 的“声母—韵母—整体认读—多音字”分层，但题库、声调规则和输入法处理要重新设计。
3. **P1 → P1（提前到 P1 首位）[调整]：飞花令 / 诗句填空**。现有诗词库和自动拼音可直接复用，玩法已被西窗烛和多个 2026 年网页项目验证，判定规则（含字、去重、词库外句子处理）有现成参考。
4. **P1：古诗词碎片重组**。参考 `bigxinxin-spec/chinese-poetry-game`，拖拽可降级为点击排序以适配手机。
5. **P1：成语接龙 / 词语链**。把词语释义、首尾字和难度结合起来。
6. **P2：成语声韵 Wordle 与每日一题**。参考 `antfu/handle`、`cheeaun/chengyu-wordle`、`AllanChain/chinese-wordle`，新增 `xyz2357/cnwordle` 的四维反馈与词库校对流程、recatools 的确定性出题；作为留存机制而非首发玩法。
7. **暂缓：听音辨字**。现有项目仍有拼音录音书面授权待归档事项，新增音频玩法应等权利边界明确后再做。

总体判断不变：先做一个不依赖新媒体素材的 P0 小游戏，比同时开发多个入口更容易验证留存、移动端输入和题库质量。

## 3. 深度竞品拆解

以下 8 项按“核心循环 / 教学设计 / 留存与变现 / 商店信号 / 题库与素材授权 / 对 Hanzis 的启示”六个维度记录。商店评论仅取抓取页面可见条目，不代表全量分布。

### 3.1 洪恩识字 + 洪恩拼音（iHuman，母语儿童）

- **核心循环**：每个汉字走“玩（互动引入）→ 认（字形字义动画）→ 练（辨形、听音找字、看字找音）→ 写（运笔）→ 说（字 → 词 → 短句）”，配每日回顾、阶段检测与趣味挑战；拼音端对应“玩、调、读、说、拼”等 9 环节。单字单局约数分钟，节奏由环节切换而非计时驱动。
- **教学设计**：1800 字分“识字启蒙 / 生活常用 / 进阶提升”三阶段；部编版板块按年级、书册、课文组织，先单字再整课测验；130 本子集绘本只用已学字编故事；拼音端 63 拼音 + 401 组合 + 28 本拼音绘本，并与识字端 1800 字联动拼读。商店文案明确引用教育部《3—6 岁儿童学习与发展指南》反对机械识字。
- **留存与变现**：家长可设使用时长、每日目标、识字速度、是否允许跳过环节，并查看识字报告；两款 App 通过“洪恩幼小衔接套装”捆绑销售。内购从月卡 ¥24 到全科永久包 ¥1,148。
- **商店信号**：识字 4.8 / 143 万，拼音 4.8 / 51 万，均在抓取前一周内更新。可见差评：“游戏成分过多，有些游戏不能关闭”“任何阶段都可以退出，孩子玩完游戏就跳过认练写”“一个账号只能同时登录一台设备”。开发者回复指出可在设置中关闭游戏环节和禁止跳过。
- **题库与素材授权**：全部为自有原创动画、儿歌、绘本，商店未声明第三方来源；不存在可复用素材。
- **对 Hanzis 的启示**：小游戏必须是学习环节中的一环，且默认不可跳过练习直接“通关”；提供家长 / 学习者可配置的“只练不玩”开关；识字与拼音互相引用（拼读练习复用已学字）与 Hanzis 字典 / 拼音 / 字帖跨模块入口的思路一致。不建议模仿的部分：动画叙事、订阅捆绑、账号体系。

### 3.2 悟空识字（宁波启点，母语儿童）

- **核心循环**：每日一课，一课学一组字（家长可设 1–10 个新字），每字“认、练、读、写、复习”，含形近字辨析、音形意练习、错字复习、隔天复习。学完一本 300 字后再进入自动复习，复习顺序按“学得最差的字最先出现”。
- **教学设计**：象形演变动画 + 西游情景；75 篇阶梯阅读把识字过渡到阅读。
- **留存与变现**：一天一课强制节奏；家长有时间管理、学习报告、二孩模式。内购年 ¥198、三年 ¥248。
- **商店信号**：4.7 / 12 万；v3.16.31 抓取前 4 天更新。可见差评：“看图识字下面已经写了正确的字，再找毫无意义”“不能把不会的字单独挑出来重学”“找不到时间提醒设置”“一天课程学完必须第二天才能开启”。开发者回复承认“图下标字”是有意设计的巩固环节。
- **题库与素材授权**：自有素材；无可复用内容。
- **对 Hanzis 的启示**：错题（错字）优先复习、按掌握度排序是可以低成本落地到 localStorage 的机制；同时要避免“题面泄露答案”和“不能自选重练”这两个被反复投诉的点。不建议模仿：强制隔日解锁。

### 3.3 成语消消消 + 成语接龙（武汉 Dobest，全年龄成语消除 / 填字）

- **核心循环**：成语消消消是“在打乱的字块中按顺序点出四字成语即消除”，另有“看图选成语”；成语接龙是纵横填字棋盘，把候选字填入空格使横竖都成成语，卡关可求助好友、看释义或用道具直接填一格。两者单局均在 1–3 分钟。
- **教学设计**：以成语识别与联想为主，2024-10 版本为成语接龙加入“温故知新 & 成语典故”，说明厂商也意识到纯消除缺少复习环。
- **留存与变现**：关卡制无尽推进；成语接龙含广告，去广告 ¥18，另有周订阅 ¥3、月订阅 ¥6 与金币包；成语消消消把“成语解释”做成内购。两款均在隐私标签中声明“使用数据用于跨 App 追踪”。
- **商店信号**：成语消消消 4.8 / 27 万（益智问答榜 #15，v6.2 2025-06-06）；成语接龙 4.8 / 14 万（字谜榜 #30，v6.2 2026-03-11，13+ 分级含广告）。可见差评集中于“没通过一个关卡就出现一次广告”“广告太多”；好评提到“针对小学初中语文差的学生很超值”。同类 Google Play 产品成語消消挑戰（4.8 / 3.51 万）差评还提到“有些成语顺序颠倒”。
- **题库与素材授权**：成语词库来源未声明；界面为自有国风美术。
- **对 Hanzis 的启示**：这类玩法留存靠“低门槛 + 无尽关卡 + 即时消除反馈”，而不是教学深度。Hanzis 的差异化应是“无广告、释义免费且有来源、错序时解释原因、通关后展示释义与例句”，正对应这些产品被投诉的点。成语接龙的纵横填字对手机触控面积要求高，P0 仍应从二字词 4×4 起步。不建议模仿：道具经济、追踪 SDK、成语解释付费。

### 3.4 西窗烛（北京西窗文化，诗词综合）

- **核心循环**：内容型 App，游戏（诗词大会、飞花令、诗词接龙、答题）作为“活动”存在于百万文库之上；可开启“智能助手”获得诗句提示；学习计划支持打卡、补卡与打卡日历。
- **教学设计**：文库按朝代、作者、选集、主题、课本（小学 / 初中 / 高中）分类；作品页含注释、译文、赏析、历代评点；配朗读、语音评测、抄写。
- **留存与变现**：会员月 ¥6、年 ¥50、高级年 ¥158，另有西窗币道具；桌面 / 锁屏小组件（诗词日历、诗词天气）作为日常触点。
- **商店信号**：4.9 / 46 万，v8.3.2 2026-09-04；支持 iPhone / iPad / Mac / Apple Watch。搜索结果中的近期负面反馈集中在“增加付费订阅项目”与“AI 对话功能闪退”，本次未在抓取页看到原文，记为二手线索。
- **题库与素材授权**：文库、辞典、鉴赏辞典来自出版物合作（商店文案列出《辞海》《汉语大词典》《唐诗鉴赏辞典》等），是版权采购模式，不可复制。
- **对 Hanzis 的启示**：“游戏依附于内容库，题目可回链到作品页”的结构与 Hanzis 诗词模块完全一致，飞花令题目应直接引用现有 11,407 篇作品与 30 首校对内容；“智能助手提示”可用本地词库检索替代 AI。不建议模仿：创作社区、会员分级、AI 智能体。

### 3.5 飞花令 - 古诗词答题（杭州家之馨，独立飞花令 App）

- **核心循环**：三种模式。经典飞花令：50 个关键字，逐关填完含该字的诗句；飞花令挑战：入门 / 进阶两档难度按主题出题；人机对战：单字飞花与主题飞花，与机器轮流出句。
- **教学设计**：诗词附注释与作者介绍，可收藏诗句；商店文案直言“原版飞花令没有诗词基础玩不转，因此做了改良”。
- **留存与变现**：会员月 $4.99、半年 $7.99、年 $9.99；宣称“广告极少”，但隐私标签声明用于第三方广告的设备标识符与诊断数据。
- **商店信号**：无评分概览；v1.0.3 2023-11-03 后无更新；类别为 Utilities；本地化语言列表 27 种但产品仅中文内容，属模板化上架。
- **题库与素材授权**：诗句来源未声明。
- **对 Hanzis 的启示**：三种模式恰好对应难度阶梯——“填空补句”最低门槛、“主题限定”中等、“轮流对句”最高；Hanzis 可只做前两种并把“人机对战”降级为“系统给出下一句示例”。该产品停更两年也说明：没有内容库支撑的独立飞花令 App 难以持续。

### 3.6 每日成语 Wordle 网页群：wordlechinese.com、recatools 每日成语、xyz2357/cnwordle

- **核心循环**：三者都是“每日同一题、6 次机会、按位置着色”。wordlechinese.com 用拼音键盘输入，答案池 7,209 条高频成语，自 2022-01-27 起按 UTC 日排队；recatools 用约 400 条常用成语作答案池、~30,000 条词典校验输入，固定置换 + 日期序号确定当日题，提示只揭示释义；cnwordle 每字分别对字、声母、韵母、声调四维着色，题目 2,600 条按《现代汉语常用词表》频级筛选。
- **教学设计**：wordlechinese 每日答案页附释义、例句与拼音并作为 SEO 落地页；recatools 强调“主动回忆优于被动阅读”；cnwordle 的四维反馈让猜错字仍能获得声韵调信息，收敛更快。
- **留存与变现**：均免费、无账号；streak 与结果存 localStorage；分享网格只含颜色不泄题；recatools 声明题目数据抓取一次后缓存、不再请求服务器。
- **商店 / 活跃度信号**：wordlechinese 答案页持续更新至抓取当日；cnwordle 创建于 2026-09-01，0 stars，无 license；recatools 为工具站的一个页面。
- **题库与素材授权**：cnwordle README 明确来源（chinese-xinhua、《现代汉语常用词表》、pypinyin）并记录 413 处读音修正；wordlechinese 与 recatools 均未声明来源。cnwordle 无 license，只能借鉴方法。
- **对 Hanzis 的启示**：每日一题的三要素——确定性出题（不依赖服务器）、答案池与校验词典分离、不泄题分享——都可以在静态站实现。Hanzis 已有 chinese-xinhua 成语 30,895 条与 `pinyin-pro` 拼音，可复刻 cnwordle 的“常用词频筛答案池 + 全量词典校验 + 拼音交叉校对”流程。声韵调四维反馈对色彩与无障碍要求高，应作为 P2。

### 3.7 HelloChinese（对外汉语综合，附 Skritter 对照）

- **核心循环**：按 HSK 分级的短课，每课混合听、选、拼、说、写；语音识别对发音打分；手写练习汉字；1000+ 分级故事与 2000+ 真人视频作为课后输入。
- **教学设计**：专设“拼音课程”给零基础学习者；简繁双支持；课程可离线下载；多设备同步进度。
- **留存与变现**：Premium $11.99/月、$25.99/季、$69.99/年，另有 Premium+；免费层可完成基础课。Skritter 则无免费层，$14.99/月、$99.99/年，核心是笔顺书写 + 间隔重复。
- **商店信号**：HelloChinese 4.9 / 2.3 万，v7.6.5 抓取前 12 小时更新；Skritter 4.7 / 789，可见差评为“试用期结束前未收到扣费提醒”。
- **题库与素材授权**：自有课程与媒体；不可复用。
- **对 Hanzis 的启示**：拼音快答可借用 HelloChinese 拼音课程的顺序（声母 → 单韵母 → 复韵母 → 声调 → 整体认读）作为难度分级依据，与 Hanzis 现有拼音模块的分类一致；Skritter 说明“写”本身可成为独立练习产品，Hanzis 笔顺模块已具备该能力。不建议模仿：订阅墙、语音评测（需服务端或大模型）。

### 3.8 dhjz/hanzi-study（开源儿童识字拼音闯关站）

- **核心循环**：面向 3–6 岁的小游戏闯关：听音识字、笔画书写、拼音、加减法，一至六年级古诗词朗读与拼音译注；2025-08 更新加入单元测验、点读模式，汉字增至 1200+。
- **教学设计**：按年级组织古诗词；关卡线性推进；家长点击标题 10 次可自定义当前关卡进度，用于多终端手动同步。
- **留存与变现**：无账号、无变现；纯离线单页，支持平板 / 手机 / 电脑与护眼模式；提供 Docker 部署。
- **活跃度信号**：226 stars、66 forks，创建 2025-06-21，推送 2026-09-10，是本次新增候选中唯一有明显社区关注度的项目。
- **题库与素材授权**：MIT 许可证覆盖代码；README 未声明汉字数据、音频与图片来源，jsDelivr 引用仓库内截图。
- **对 Hanzis 的启示**：它证明“静态单页 + 本地进度 + 多设备手动同步”可以支撑一个被持续使用的儿童学习站，与 Hanzis 的静态导出定位相同；“古诗词按年级分级”可直接借鉴到诗词题库的难度标签。代码可在保留 MIT 声明的前提下参考结构，音频与图片一律不复制。

## 4. 值得借鉴的实现模式

### 4.1 短局 + 即时反馈

成熟项目大多把一局压缩到几十秒或几分钟内：

- `PinyinGame` 用 180 秒倒计时、答对加分、错误反馈和自动换题构成循环。
- `chengyu-wordle` 用固定次数猜测和颜色提示制造“再试一次”的动机。
- `xixi-poem-game` 用 30 秒限时、答对加时、答错扣生命值制造节奏。
- 成语消消消 / 成語消消挑戰用“点选即消除、方块下落刷新”把反馈压到亚秒级；飞花令诗词擂台用每回合 20–60 秒倒计时与“回车即判”。

Hanzis 的第一版应避免复杂账号和服务端排行榜，先把“出题 -> 作答 -> 反馈 -> 下一题 -> 本地进度”做完整。

### 4.2 内容数据与游戏逻辑分离

`handle`、`chengyu-wordle`、`hanzi-match-game` 和 `xyz2357/cnwordle` 都体现了内容层独立于界面层的价值：

- 成语、拼音、释义、难度、标签应是可版本化的数据文件。
- 游戏运行时只读取经过校验的题目，不在组件中散落大量题目。
- 自定义字库应走明确的数据格式、重复项检查和最小题量检查。
- 每条内容应保留 `source`、`license`、`reviewStatus` 等元数据，避免“题库能跑但来源说不清”。
- 答案池与校验词典分离（cnwordle：2,600 题 / 56,075 可猜；recatools：400 题 / 30,000 可猜）：答案只出常用词，输入校验放宽到全量词典，兼顾公平与容错。
- 读音需交叉校对（cnwordle 用 pypinyin 修正源数据 413 处错读；4yu 承认 Web Speech API 多音字读错）：Hanzis 已有 `poetry-pinyin-overrides.json` 纠音机制，成语题库应复用同一流程。

建议的通用题目结构：

```ts
type LearningItem = {
  id: string;
  kind: "hanzi" | "word" | "chengyu" | "poem";
  prompt: string;
  answer: string;
  pinyin?: string;
  explanation?: string;
  level: 1 | 2 | 3;
  tags: string[];
  source: string;
  license?: string;
  reviewStatus: "unreviewed" | "reviewed";
};
```

### 4.3 难度不是单纯加速

`AllanChain/chinese-wordle` 的价值在于它把难度放在提示数量和获得提示的条件上，而不只是减少时间。可以迁移到 Hanzis：

- 入门：显示完整拼音或释义，允许跳过。
- 进阶：只显示声母、韵母、首字或部件。
- 挑战：限制错误次数，加入重复字和近义词干扰。

飞花令 App 的三档（填空补句 → 主题限定 → 轮流对句）与 HelloChinese 的拼音课程顺序（声母 → 单韵母 → 复韵母 → 声调 → 整体认读）提供了两条现成的难度阶梯。

### 4.4 学习闭环：练习不能被游戏绕过

商店差评给出了反面清单：

- 洪恩识字：“游戏成分过多”“任何阶段都可以退出，孩子玩完游戏就跳过认练写”。
- 悟空识字：“看图识字下面已经写了正确的字”“不能把不会的字单独挑出来重学”。
- 成语消除类：“成语解释要内购”“每过一关一次广告”。

对应到 Hanzis：题面不得泄露答案；错题进入本地“待重练”队列并优先出现；通关后必须展示释义、拼音与例句；提供“只练不玩”配置。

### 4.5 非惩罚式反馈与收集

`Nitkz/pinyin-island`（无 Game Over、答错不扣命、47 个拼音“宝物”收集）与洪恩 / 叫叫的收集玩法说明：面向低龄的拼音练习应弱化失败，强化“已掌握清单”。这与 4.3 的“挑战档限制错误次数”不冲突，应按难度档切换反馈策略。

### 4.6 分享与本地进度可以后置到最小版本

`chengyu-wordle` 的结果分享和 `xixi-poem-game` 的成就系统值得保留为扩展点，但不应阻塞第一个可玩的版本。首版优先使用 `localStorage` 保存：

- 今日完成次数和连续天数。
- 每个游戏的最高分、最快时间和已解锁关卡。
- 题库版本号，避免题库更新后旧进度解释错误。

后续加入每日一题时，沿用 recatools 的做法：当日题由“固定置换 + 日期序号”确定，不依赖服务器；分享结果只含颜色网格与题目 ID，不含答案。

### 4.7 不适合 Hanzis 定位的商业模式

以下机制在竞品中普遍存在，但与 Hanzis“无账号、静态导出、无广告”的定位冲突，明确不采用：账号与多设备同步、订阅 / 会员分级、道具经济与养成（升官、门客）、插屏广告、第三方追踪 SDK、需要服务端或大模型的语音评测与 AI 判诗。

## 6. 推荐的首个自研版本

### 方案：汉字词语消除

选择它的理由：

- 不依赖录音、TTS 或第三方音乐，避开当前授权待办。
- 规则可在一屏内解释，移动端点击操作比复杂输入更稳。
- 能直接连接现有字典、词语和汉字内容，不需要先做拼音解析器。
- 具备自然的关卡、提示、重开、星级和本地进度扩展点。
- `lapsea/hanzi-match-game` 已验证这一玩法方向，商店成语消除类以数十万评分验证了更大规模的接受度；但两者都没有可复用的开放题库，只把它们当作交互参考。

建议的第一版规则：

1. 棋盘 4×4 起步，保证手机屏幕上每个格子有足够的触控面积。
2. 每关由 8 个二字词组成，共 16 个汉字；只有按正确词序点选才算成功。
3. 点错时说明“顺序不对”“不是本关词语”或“先完成其他组合”，不要只显示失败。
4. 提示只高亮一个合法词对，并消耗一次提示或星级。
5. 通关后展示词语释义、拼音和一个例句，避免游戏与学习脱节；释义免费且标注来源。
6. 题库只使用已审校内容，题目记录来源和授权状态。
7. 点错的词进入本地“待重练”列表，下一关优先复用其中的字。

建议路由：`/games/hanzi-match`

> 实现状态（2026-09-25）：已按上述规则上线本地版本 `/games/hanzi-match/`，入门 / 进阶 / 挑战各 5 关共 120 词；挑战关覆盖首尾相连、正反成词与多音字。第 7 条“下一关优先复用待重练的字”简化为“待复习词语”清单：用过提示或点反顺序的词进入清单，之后在同一关顺利找到即移出。题库为站内编写，读音经 pinyin-pro 交叉校验，释义与例句待人工审校。
>
> 后续实现（2026-09-25）：`/games/pinyin-quiz/` 拼音快答（第 5 节 P0 第二项）与 `/games/feihua/` 飞花令 · 诗句填空（P1 首位）已上线本地版本，另设 `/games/` 目录。拼音快答支持不标调与标调（数字或调号）、ü 写作 v、轻声可省略，按“声调不对 / 声母对了 / 拼写不对”反馈，并提供不限时 20 题以满足可关闭时限。飞花令采用四选一补字而非自由输入：自由输入需要全库诗句索引与输入法处理，留作后续；“主题限定”档与人机轮流对句也未实现。题源从已导入的诗词快照中课本与选集篇目生成，排除近现代作品。
>

### 后续共用组件

如果 P0 验证通过，再抽取轻量的游戏壳层，而不是一开始建设完整游戏引擎：

- `GameShell`：标题、返回、暂停、进度和结果页。
- `QuestionCard`：题面、提示和解释。
- `GameFeedback`：正确、错误、连击、提示和完成状态。
- `ProgressStore`：版本化本地存储，含待重练队列。
- `ContentValidator`：题目重复、空答案、字符数、题面泄露答案和来源状态检查。
- `DailySeed`：由固定置换 + 日期序号选题，供后续每日一题复用。

这些组件可以被拼音快答、飞花令、古诗词重组和成语游戏复用；题型规则仍应保留在各游戏模块中，避免一个“大而全”的状态机。

## 7. 许可证、题库和素材边界

这次调研最重要的复用结论不是“哪个仓库最好”，而是“代码、题库、图片、字体、音频不能视为同一种资产”。

- MIT 和 BSD-3-Clause 通常允许在满足保留版权和许可文本等条件下使用代码，但仍要逐项检查仓库中的第三方依赖和数据来源。
- 没有 `LICENSE` 或仓库 API 未返回许可证的项目（含本次新增的 cnwordle、poetry-game、pinyin-island 等），只作为玩法和架构参考，不直接复制代码。
- GPL-2.0 项目（CNWordle）的代码不纳入静态站复用范围，只参考思路。
- `chengyu-wordle` 的 README 明确区分原始数据、处理后题库和高频成语数据；Hanzis 若采用类似数据，必须记录来源和再分发条件。
- `AllanChain/chinese-wordle` 与 `xyz2357/cnwordle` 的 README 指出成语和拼音参考 THUOCL、汉典、chinese-xinhua、《现代汉语常用词表》、`pypinyin` 等来源；这些上游数据的授权边界不能由下游仓库的许可证自动覆盖。Hanzis 已导入的 chinese-xinhua 快照及其许可说明可直接作为成语题库来源。
- `xixi-poem-game` 虽声明 MIT，但 README 同时说明背景音乐和音效来自第三方版权方，不能随 MIT 代码一起复制；`dhjz/hanzi-study` 为 MIT，但音频与图片来源未声明，同样只参考代码结构。
- 商店类产品（洪恩、悟空、叫叫、Dobest、西窗烛、HelloChinese 等）的界面、美术、音频、题库与文案均为商业版权内容，本文只记录公开页面可见的玩法与规则，不复制任何素材、关卡数据或文案。
- X 帖子与第三方聚合站（MWM、下载站）的数据只作线索，不作为结论依据。
- 当前 Hanzis 的拼音录音仍有书面授权说明待归档，因此本报告不建议把任何上游音频纳入新小游戏。

## 8. 实施建议与验收门槛

### 实施顺序

1. 先为 `/games/hanzi-match` 建立独立页面和本地题库，不动现有五个核心入口。
2. 先用 15 至 30 关经过人工审校的内容验证规则、手机布局和重复游玩。
3. 再补拼音快答，先支持不带调输入，明确多音字和声调策略后再扩展。
4. 随后做飞花令 / 诗句填空，直接复用诗词库与自动拼音；判定规则参考 4.2 与飞花令诗词擂台的“含字 + 去重 + 词库外提示”。
5. 最后考虑成语 Wordle、每日一题、分享和排行榜；分享功能应使用可版本化的题目 ID，而不是把答案直接写入 URL。

### 最小验收门槛

- 桌面和手机宽度下无横向溢出，所有主要触控目标不小于项目现有规范。
- 首屏能在无需注册、无需联网 API 的情况下开始游戏。
- 每道题都能回溯到题库记录的来源和审校状态。
- 题面不泄露答案；错误反馈能解释原因；结果页能回看答案、拼音和释义。
- 刷新页面后进度不丢失，题库版本变化不会错误恢复旧关卡。
- 不引入未确认授权的音频、图片、字体或题库文件。
- 不引入广告、追踪 SDK、账号或付费墙。

## 9. 本次调研的证据边界

- “玩法存在”依据仓库 README、商店页描述或关键源码确认。
