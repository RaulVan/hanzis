# 诗词拼音生成与纠音

本站保留原有 30 首人工注音；扩展诗词正文使用固定版本 `pinyin-pro@3.29.4` 构建期生成，阅读页按需加载，不调用远程注音 API。借鉴 pinyin-annotator 的引擎方案，未复制其 HTML、字体、现代口语轻声/儿化规则或在线引擎更新逻辑，也未引入其完整分词词典。引擎 MIT 许可见 `licenses/pinyin-pro-MIT.txt`。

## 使用

扩展诗词首次默认关闭“显示拼音”。打开后加载当前作品所在拼音分片；选择保存在当前浏览器，切换作品、刷新时沿用。原有 30 首在尚未设置偏好时仍默认显示。存储不可用时仅当前页面会话保留选择。

扩展作品标注“自动注音，部分多音字待校对”。未识别字不注音，但仍占据拼音数组中的空位。加载失败、版本或正文不匹配时继续显示原文，并提供重试。所有自动作品仍属于机器生成，命中少量校对诗句不将整篇升级为人工校对。

本轮只影响正文阅读：标题、作者、译注不自动注音。朗读仍由系统语音处理；生成字帖仍使用现有 cnchar 链路，不宣称与阅读页纠音完全一致。

## 构建与更新

```sh
npm ci
npm run poetry:pinyin  # 仅刷新拼音资源
npm run build          # 自动准备源数据分片、拼音及全站导出
npm run release:verify
```

- 原始 `data/haitang-source.json.gz` 不修改。
- `scripts/prepare-poetry-pinyin.ts` 逐行使用 `pinyin(text, { type: "all", toneSandhi: false })`，确认返回原字符与正文逐码点一致后，提取每个汉字的读音。
- 优先级：作品位置纠音 > 诗句规则 > 引擎默认。诗句规则合并原有 30 首校对诗句与显式规则，同句由显式规则替换；在行内按长句优先匹配，忽略标点以兼容来源排版，不跨换行。
- 生成 `public/poetry/pinyin/00.json` 至 `7f.json` 共 128 个分片，沿用作品数字 ID 取模。记录每篇正文 SHA-256、逐行汉字拼音数组、缺失读音数和命中纠音的行数。
- `data/poetry-pinyin-manifest.json` 是需提交的生成清单；静态分片由构建重建，不提交 Git。它记录源快照、引擎、生成规则版本、统计及每个分片 SHA-256。
- 生成器、引擎、校对诗句、纠音表不变时，正文 SHA-256 匹配且旧分片校验通过的条目会复用；新增或修改作品重新生成。冷构建不存在缓存时生成全库。删除作品不会遗留在新分片中。
- 引擎或规则更新会重新生成全库；修改后检查清单统计与人工抽检。浏览器请求携带独立拼音版本，并校验分片及正文，避免原文未变、纠音已更新时继续使用旧读音。

## 人工纠音

编辑 `data/poetry-pinyin-overrides.json`，默认两个空表。重复出现且读音确定的完整诗句可加入 `phrases`，按字用空格分隔；不要使用单个多音字作为全局规则。

```json
{
  "phrases": {
    "朝辞白帝彩云间": "zhāo cí bái dì cǎi yún jiān"
  },
  "works": {}
}
```

特定作品优先使用 `works`：键为来源作品数字 ID；`textHash` 取该作品生成记录中的值；`readings` 的键为正文从 0 开始的 **Unicode 码点位置**（不是 UTF-16 下标），含标点与换行，CRLF 统一为 LF。每项包含原字 `char` 与读音 `pinyin`。结构示意：

```text
works[作品ID] = {
  textHash: 正文SHA256,
  readings: { "码点位置": { char: "原字", pinyin: "读音" } }
}
```

作品不存在、正文摘要变化、位置越界、原字不符或拼音格式错误都会阻止生成，避免旧纠音套到新正文。纠音后运行 `npm run poetry:pinyin`，审阅清单变化，再运行相关测试和构建。

## 验证边界

拼音覆盖率不等于准确率。现代词典不能直接保证古诗文的通假字、古义、人名、地名读音正确。引擎关闭“一／不”变调、不合并儿化音，但自动轻声仍需校对。扩展区生僻字按 Unicode 码点处理，无法识别时保持空读音。

`tests/poetryPinyin.test.ts` 核对全库正文绑定、字音数量、缺失统计及纠音优先级；浏览器测试覆盖首次默认、偏好记忆、人工注音保留、已知纠音、失败重试、部分缺失和长文。
